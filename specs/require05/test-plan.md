# 实时信息通道测试计划

> 配套文档：`requirement.md`（需求）、`plan.md`（架构与实施方案）、`dev-plan.md`（开发计划）
> 测试对象：`ruoyi-common-websocket` 模块（+ 共享 `ruoyi-api-websocket`）+ 业务推送接入 + 微前端消息总线

---

## 一、概述

本计划覆盖实时信息通道的完整链路测试，验证目标：

1. WebSocket 连接建立、鉴权、心跳、断连清理的正确性
2. 三级主题订阅（主类/子类/具体业务ID）与前缀匹配路由的准确性
3. RabbitMQ 生产/消费、多实例会话与订阅一致性
4. 微前端主应用单连接复用、消息总线派发、断线重连重订阅
5. 异常与性能场景下的稳定性

---

## 二、测试范围

**在范围内：**
- 会话管理、订阅管理、消息路由（定向/前缀匹配/广播）
- RabbitMQ 消息生产与消费、JSON 格式正确性
- 订阅/退订/查询 REST 接口
- 前端 WebSocket 客户端、订阅封装、消息总线派发、子应用接入
- 心跳、超时清理、断线重连
- 并发与基础性能（连接数、推送吞吐、消息堆积）

**不在范围内：**
- 业务模块自身业务逻辑正确性（仅验证推送触发点）
- 消息持久化/离线补发（本期不实现）
- 生产级压测与容量规划

---

## 三、测试环境

| 项 | 说明 |
|----|------|
| 后端 | 内嵌 `ruoyi-common-websocket` 的服务，单实例 + 双实例（验证多实例一致性） |
| 中间件 | RabbitMQ（fanout 交换机 + 每实例队列）、Redis（Redisson） |
| 业务服务 | system（通知示例链路） |
| 前端 | 微前端主应用（RuoYi-UI）+ HIS 子应用 |
| 测试工具 | Postman（REST）、浏览器 DevTools（WebSocket 帧）、`wscat`/脚本（压测连接） |

> 多实例一致性用例需至少部署 2 个内嵌 websocket 模块的服务实例。

---

## 四、测试策略与层级

| 层级 | 目标 | 用例组 |
|------|------|--------|
| 单元测试 | 主题工具、前缀匹配、校验逻辑 | `WS-TP-*` |
| 接口测试 | 订阅/退订/查询 REST、握手鉴权 | `WS-SUB-*`、`WS-SES-*` |
| 集成测试 | MQ 生产→消费→推送、多实例一致性 | `WS-MQ-*` |
| 端到端测试 | 业务事件 → 客户端推送、前端总线派发 | `WS-RT-*`、`WS-FE-*` |
| 异常与性能 | 断连、超时、消息堆积、并发连接 | `WS-EX-*`、`WS-PF-*` |

## 五、测试用例设计

### 5.1 主题工具与校验（WS-TP）

| 用例ID | 用例名称 | 步骤 | 预期结果 |
|--------|----------|------|----------|
| WS-TP-001 | 合法三级主题 | 校验 `his/order/10086` | 通过，拆分为 3 段 |
| WS-TP-002 | 合法两级主题 | 校验 `system/sysNotice` | 通过，拆分为 2 段 |
| WS-TP-003 | 合法单级主题 | 校验 `system` | 通过，拆分为 1 段 |
| WS-TP-004 | 非法字符 | 校验 `his/order#x` | 拒绝并返回错误 |
| WS-TP-005 | 空段 | 校验 `his//order`、`/his` | 拒绝 |
| WS-TP-006 | 超长段数 | 校验 `a/b/c/d`（4 段） | 拒绝 |
| WS-TP-007 | 前缀生成 | `prefixes("his/order/10086")` | 返回 `["his","his/order","his/order/10086"]` |
| WS-TP-008 | 边界防误判 | 前缀 `his/order` 对消息 `his/orderX/1` | 不命中（按段边界） |

### 5.2 会话管理（WS-SES）

| 用例ID | 用例名称 | 步骤 | 预期结果 |
|--------|----------|------|----------|
| WS-SES-001 | 合法握手 | 携带有效 token 连接 `/websocket` | 连接成功，会话写入本实例内存 |
| WS-SES-002 | 非法握手 | 携带无效/缺失 token 连接 | 拒绝连接 |
| WS-SES-003 | 正常断开 | 客户端主动 close | 会话移除，订阅同步清理 |
| WS-SES-004 | 心跳保活 | 客户端周期发送 `ping` | 服务端更新心跳时间，不超时 |
| WS-SES-005 | 心跳超时清理 | 客户端停止心跳 | 超过阈值后会话被清理，订阅清理 |
| WS-SES-006 | 异常断开 | 网络中断（模拟） | 定时清理触发，会话与订阅均清理 |

### 5.3 订阅管理（WS-SUB）

| 用例ID | 用例名称 | 步骤 | 预期结果 |
|--------|----------|------|----------|
| WS-SUB-001 | 订阅成功 | `POST /subscribe` 提交 1~3 级主题 | 写入 `global:ws:sub:{topic}` 与反向索引 |
| WS-SUB-002 | 重复订阅幂等 | 重复提交同一主题 | 不产生重复订阅，Set 去重 |
| WS-SUB-003 | 退订 | `POST /unsubscribe` | 从正向索引移除；set 空则删 key |
| WS-SUB-004 | 查询订阅列表 | `GET /websocket/subscription`（Sa-Token 识别用户） | 返回该用户全部主题 |
| WS-SUB-005 | 未认证订阅 | 未登录/无效 token 调订阅接口 | 返回错误 |
| WS-SUB-006 | 越权订阅 | 用他人 token 订阅他人主题 | 鉴权拦截，拒绝 |
| WS-SUB-007 | 非法主题 | 提交非法主题 | 拒绝并返回错误码 |
| WS-SUB-008 | 断开清理订阅 | 订阅后断开连接 | 该客户端的订阅被全部清理 |

### 5.4 消息路由（WS-RT）

| 用例ID | 用例名称 | 步骤 | 预期结果 |
|--------|----------|------|----------|
| WS-RT-001 | 定向推送 | 发布 `sessionKeys=[1001]` | 仅 userId=1001 收到 |
| WS-RT-002 | 模块级命中 | 订阅 `his`，发布 `his/order/10086` | 命中并推送 |
| WS-RT-003 | 业务级命中 | 订阅 `his/order`，发布 `his/order/10086` | 命中并推送 |
| WS-RT-004 | 业务ID精确命中 | 订阅 `his/order/10086`，发布同主题 | 命中并推送 |
| WS-RT-005 | 不命中 | 订阅 `his/patient`，发布 `his/order/10086` | 不推送 |
| WS-RT-006 | 广播 | 发布 `type` 与 `sessionKeys` 均空 | 全部在线客户端收到 |
| WS-RT-007 | 路由优先级 | 同时满足定向与订阅 | 仅按定向推送，不重复推送 |
| WS-RT-008 | 多订阅并集去重 | 客户端同时订阅 `his` 和 `his/order` | 同一消息只收到一次 |

### 5.5 RabbitMQ（WS-MQ）

| 用例ID | 用例名称 | 步骤 | 预期结果 |
|--------|----------|------|----------|

## 七、准入 / 准出标准

**准入（开始系统测试前）：**
- 内嵌 `ruoyi-common-websocket` 的服务可正常启动
- 订阅/退订/查询接口可用
- 业务示例链路（system 通知）可端到端推送

**准出（通过标准）：**
- 5.1~5.7 全部用例 100% 执行
- 高优先级用例（鉴权、前缀匹配、多实例一致性、断线重连）零缺陷
- 中低优先级用例无遗留严重/致命缺陷
- 性能用例（WS-PF-*）达到阈值且无消息丢失

## 八、缺陷管理

| 级别 | 定义 | 处理要求 |
|------|------|----------|
| 致命 | 推送丢失、错发、鉴权失效、服务崩溃 | 立即修复，阻断准出 |
| 严重 | 订阅清理残留、重连订阅丢失、多实例不一致 | 准出前必须修复 |
| 一般 | 日志不完整、返回码不规范 | 评估后修复或记录 |
| 轻微 | 文案、样式 | 记录，可延后 |
